# Host-owned coding tools

`CodingGrant` and `SandboxTools` connect the bounded offline executor to `Agent` through an explicit Python embedding argument. A grant names its `mask`, and the host names the masks it accepts with `allowed_masks` (a tuple; default `('coding',)`). A mask outside that set, or an empty or malformed set, fails closed with no fallback.

The embedding host constructs a frozen `CodingGrant` using dedicated canonical source/staging directories, an immutable artifact allowlist, and finite limits. Keep both directories frozen against host mutation for the adapter lifetime. The model receives only `sandbox_exec(command)`. Host paths, artifact names, quotas, mask and call limit cannot be supplied in tool arguments. Each call starts from the original source snapshot; combine edits and tests into one command. No automatic persistence or source writeback is performed.

Use only with `Agent(request_budget_isolated=True, request_admission=..., sandbox_tools=adapter)`. Exact adapter and admission classes are required. Workspace research restrictions reject the combination. Isolated hooks, spawners, jobs and MCP remain unavailable. Automatic compaction is disabled. Unknown tools and code-mode dispatch cannot reach the general toolkit. Host event callbacks remain trusted code, not a sandboxed extension boundary.

The adapter serializes calls and admits at most 1–8 attempts (default 4); failed execution consumes an attempt and closes the adapter because cleanup may be unconfirmed. The existing per-sandbox memory/process/CPU/tmpfs/output limits remain in effect. `close()` waits for active bounded work before rejecting future execution and clearing exported bytes. It is not asynchronous cancellation. Limits are per adapter, not global or durable across adapter reconstruction. Reconstructing it is new host authorization and must never be an automatic crash retry. Limits do not span adapters: an embedding that runs several adapters at once supplies its own job-wide accounting and concurrency limit.

Tool results explicitly label shell/test output untrusted and expose only hashes and sizes of exported artifacts. The host retrieves candidate bytes through `adapter.artifacts()` for independent inspection. Neither return codes nor output hashes certify correctness. A subsequent serialized call clears prior candidates even when invalid, exhausted or failed; a concurrent busy rejection leaves the active call as result owner. An Agent gate denial never calls the adapter and may leave its earlier candidate bytes available: `artifacts()` refers to the last serialized adapter execution, not the last Agent tool attempt. The host must pair bytes with that execution result and its hashes. No self-acceptance is supplied.

CLI isolated mode is tool-free unless `--request-budget-sandbox-grant FILE` names a host-written grant JSON (the `CodingGrant` fields; `artifacts` and `allowed_masks` as lists); it requires `--request-budget-isolated`, and unknown fields are rejected. The adapter does not verify provider tariffs, request bounds, or replay of tool calls after a crash; the embedding host is responsible for those. Its tests use a synthetic transport and a real local sandbox, so they say nothing about provider billing.
